# 简历项目描述：ACIS 农业病害诊断与决策支持原型

> 用途：求职简历 / 面试项目介绍。数字与边界均来自仓库实测（`reports/acceptance_20261024.md`、`reports/experiment_audit_20261024.md`）。
> 说明：核心多智能体链路沿用已有 ACIS 原型；以下"我负责/实现"的部分指本次 MVP 交付化工作，可按你实际参与范围调整措辞。

---

## 一、项目一句话

**基于 LangGraph 的温室作物病害诊断与处置建议原型**：把一次自然语言问诊拆成
"感知 → 记忆 → 专家 → 辩论 → Critic → Judge"的可审计流程，输出诊断、置信度、风险与行动建议；
外部模型不可用时自动回退确定性规则链路。支持 CLI / TUI / FastAPI 三入口，离线可跑。

---

## 二、解决的农业业务问题

温室种植者在病害早期往往只能拿到一个"黑盒"诊断：不知道为什么这样判、依据了哪些证据、
什么情况下应该弃权或转人工。ACIS 把问诊过程拆成可追溯的证据链，并明确人工复核边界：

- 输入：作物 + 症状/环境描述（如"番茄叶片黄斑、叶背灰色霉层"）；
- 输出：首选病害、置信度、风险等级、是否需人工复核、6 条行动建议、辩论共识/冲突、KG 校验、推理摘要；
- 不自动施药/灌溉，只给建议；人工可通过反馈/结果回灌影响后续案例召回。

覆盖范围：4 作物 / 7 病害知识库（番茄叶霉病、早疫病；黄瓜霜霉病；甜菜褐斑病、根腐病；
棉花黄萎病、枯萎病）。传感器/天气为模拟数据；图片默认为 mock；这些边界在文档中明确标注。

## 四、技术选型与工程取舍

| 选择 | 理由 | 代价/边界 |
|---|---|---|
| **LangGraph 主图 + 规则回退** | 主图表达多阶段协作；规则路径保证无外部依赖也能跑 | 两条路径需维护一致性；回退时能力降级 |
| **规则 Judge 默认、LLM Judge 可选** | 离线、确定性、零 Token；LLM 只在需要结构化融合时启用 | LLM 路径需 key；真实质量未做多 seed 验证 |
| **RAG/KG 有内存回退** | 无 Qdrant/Neo4j 也能演示；知识证据可审计 | Qdrant/Neo4j 真实检索质量未独立评测 |
| **多 Agent + Debate/Critic** | 让冲突显式化、可降权，提升可解释性 | 未证明准确率优于裸基线；真实 LLM 路径延迟高 |
| **统一 Trace + SQLite 审计** | 每个结论可回溯、可导出；支持反馈回灌 | 交互式运行默认不落 trace 文件，需显式 `--trace-out` |
| **模拟传感器/天气** | 无需硬件即可端到端演示 | 不是真实田间数据，不能用于生产结论 |
| **固定 fixture 离线评测** | 零外部依赖、可重复、可进 CI | 只覆盖 12 个固定场景，不代表泛化 |

**明确没有做的**：真实田间数据、真实视觉模型质量验证、自动执行工具、生产并发/SLA、
完整架构优于基线的结论。

## 五、端到端能力（实测）

```text
自然语言问题
  → 上下文解析（作物/温室/意图）
  → 感知（传感器/天气模拟；视觉可选）
  → 记忆（RAG / KG / 历史案例 / 经验回放）
  → 专家（病理规则+知识库；气象/栽培/经济/生态）
  → Debate（冲突/共识）→ Critic（规则降权）
  → Judge（规则/可选 LLM）
  → 诊断 + 置信度 + 风险 + 行动建议 + 证据链
  → SQLite 决策审计 + 统一 Trace
```

三个入口均实测：
- CLI：规则 8–9s 冷启动（预热后 1.4–2.7s），LangGraph 9s；输出完整裁决与 12–15 条 Agent 轨迹；
- API：`GET /health` 200；`POST /diagnose` 200，返回 decision/confidence/judge_mode/`trace_id`/10 阶段/decision_id；
- TUI：6 个演示场景；同环境上一轮实测 12.2s 跑通场景 1（本轮沙箱无法非交互回放）。

## 七、故障定位、评测与可靠性贡献

- **评测口径审计**：发现 R3/Phase 4.2-R 报告中的 "accuracy" 实际是 factor coverage（`generate_stability_report.py:66-75`），
  阻止了把不同口径误当诊断准确率；发现 C1 ECE 差异来自 `challenge_scorer.py:154` 浮点分箱边界。
- **故障可观测性**：把 LLM Judge 的 10 类失败（认证/计费/限流/超时/连接/格式等）统一为
  `fallback_reason_code` + `judge_runtime` + 脱敏日志；故障注入验证服务不中断。
- **静默失败治理**：持久化失败、LangGraph 回退、自一致性采样失败从"不可见"改为可记录。
- **可复现性**：`--seed`、`--trace-out`、`.env.example`、依赖锁、`pytest.ini`、固定离线评测；
  两次评测输出哈希一致。

## 八、边界与未完成（面试时主动说明）

- 传感器/天气是**模拟数据**；视觉默认 mock；不是真实田间系统；
- LLM Judge 真实质量只做了单次连通验证；置信度校准实验只覆盖 C1、2 个 seed、13–24 有效样本；
- Docker 未在本环境构建；Web UI/MCP Server/Phase 4–6 评测链未验证；
- 用户工作树仍有未提交改动 + `tests/fixtures/` 未跟踪，fresh clone 与验证树不完全一致；
- 普通 Windows 环境未实测（当前只有受限沙箱），测试全绿需在普通环境复跑。

## 九、简历条目（可直接改写）

**版本 A（通用后端/AI 应用）**
- 基于 LangGraph 与规则回退构建农业病害诊断原型，打通"感知→记忆→专家→辩论→Critic→Judge→审计"全链路，支持 CLI/TUI/FastAPI 三入口与离线运行。
- 设计统一 Trace（10 阶段）与 SQLite 决策审计，新增 `--trace-out`/trace_id 输出；实现 LLM 故障分类、脱敏与自动回退，故障注入验证服务不中断。

**版本 B（算法/评测方向）**
- 在 24 例农业挑战集上完成 C0/C1/C2 真实 Judge 基线（seed42，72 次调用零回退），复算 label accuracy 与 ECE，定位分箱口径缺陷并记录负向结果。
- 实现自一致性置信度链路与规则回退统计，区分正常回答/回退/无效样本；提出同条件多 seed + 配对检验的最小补充实验方案。

**版本 C（一句话版）**
- 农业病害诊断多智能体原型：LangGraph + 规则回退、统一 Trace、可复现离线评测；如实报告"完整架构未优于裸基线"。

## 十、面试问答准备

| 问题 | 建议回答 |
|---|---|
| 为什么规则 + Agent 混合？ | 规则保证离线、确定性、可回退；Agent 负责证据聚合与冲突显式化；LLM 只做可选融合。 |
| 多 Agent 真的更强吗？ | 不声称更强。挑战集单 seed 上 C1 19/24 未优于 C0 20/24；我们把它定位为可解释的证据聚合。 |
| 效果怎么验证？ | 12 例固定 fixture 离线回归 + 24 例挑战集实验；区分"可复现离线"与"真实 LLM 条件"；报告有效样本与回退率。 |
| 可靠性做了什么？ | 10 类 LLM 失败分类、脱敏、自动回退、决策审计、Trace 导出；已知静默路径在验收报告中列出。 |
| 你个人做了什么？ | MVP 交付化：Trace 出口、API 边界、视觉字段修复、故障日志、pytest/env/README、离线评测与契约测试、实验口径审计。 |
| 最大限制？ | 模拟数据、单 seed 实验、真实 LLM 质量未验证、Docker/前端未验证；不能当生产系统。 |
